# 中文优先的单次听写接入

用户明确纯英文不是当前重点后，对 158 条语音、各三轮的冻结结果按语言重新拆分，并采用 draft-v7 作为 Realtime 的口语整理主体。普通听写只转写口述正文，翻译请求不会触发 Agent。

## 三轮既有结果的重新统计

按口述素材是否含汉字、拉丁字母分类；中英混合包含中文句子中的英文术语。三个重复轮次共享合成音频，不是独立真人盲测，也不是总体准确率承诺。

| 方案 | 纯中文 /294 | 中文与中英混合 /402 | 中文与混合请求耗时中位数 |
| --- | ---: | ---: | ---: |
| 原单次 | 219（74.5%） | 315（78.4%） | 768.5 ms |
| 原单次＋Flash | 250（85.0%） | 351（87.3%） | 1340 ms |
| 新单次 | 273（92.9%） | 367（91.3%） | 877.5 ms |

新单次中文与混合每轮分别 124/134、123/134、120/134；原两次为 117/134、115/134、119/134。中英混合的严格匹配单看为新单次 94/108、原两次 101/108，差异包含逗号、术语空格和残留口头词。不能把总体改善解释为所有子项均更好。

纯英文新单次 51/72、原两次 67/72，保留了可重复 can→can't 的已知退化。中文仍有远距离收件人改口、数字书写和少量口头词问题。用户按中文优先接受此取舍。

## 新单次之后再加 Flash 的抽样

按用户要求不重跑全量，选择 16 条已知难例及控制样本，使用第一、三轮的新单次冻结输出，各补跑一次实际生产 `DictationRefinement.refine`，共 32 次文本请求。包含口头词、指示词重起、改口、数字、列表、语气、引语、否定词和中英术语；这是偏向难例的诊断抽样。

| 方案 | 同一抽样 /32 | 请求耗时中位数 |
| --- | ---: | ---: |
| 原单次 | 23 | 787 ms |
| 原单次＋Flash | 23 | 1331.5 ms |
| 新单次 | 20 | 941 ms |
| 新单次＋Flash | 24 | 1514.5 ms |

新加 Flash 修复 6 次、退化 2 次：修复部分口头词和远距离收件人改口，但两次把引语“不要不要改”删为“不要改”。2 次超时按生产规则返回首次结果。组合耗时是冻结的 Realtime 请求耗时加本次 Flash 耗时，不是重新测量的同一次端到端时间；不能把抽样通过率与全量通过率直接比较。

因此保留两档：轻度整理只做一次 Realtime 生成，二次整理在同一结果上再调用 Flash；不宣称二次整理总能改善结果。全局和应用规则的既有选择按 #175 的迁移保持。
